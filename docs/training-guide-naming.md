# 강사교육 수업지도안 — 이름 짓기 계획

> `강사양성` 메뉴 안에 **강사가 읽는 수업지도안**을 프로그램 종류별로 넣기 위한
> 이름 계획. 코드를 쓰기 전에 **말부터 정리**한다 — 이 앱은 이미 '계획' 이라는 말이
> 세 군데서 서로 다른 뜻으로 쓰이고 있어서, 넷째를 그냥 얹으면 아무도 구분 못 한다.

---

## 0. 결론 세 줄

1. **메뉴는 `강사교육`** — `강사양성` 을 여기로 바꾸고 그 안에 탭 두 개
   (`양성과정` / `수업지도안`). 메뉴 줄은 하나도 안 늘어난다.
2. **지도안 이름은 짓지 않는다.** 프로그램을 고르면 **프로그램 이름이 곧 지도안 이름**이고,
   목록은 `/apps` 와 똑같은 **주제별 트리**로 묶인다 — "프로그램 종류별" 이 공짜로 된다.
3. 겹치는 말이 이미 셋 있으니 **읽는 사람**으로 가른다 —
   학교가 읽으면 `강의계획서`, 강사가 읽으면 `수업지도안`, 원본 파일 보관은 `계획안 첨부`.

---

## 1. 지금 이 앱에 '계획' 이 이미 세 개다

새 이름을 정하기 전에, **지금 뭐가 헷갈리는지**부터 봐야 한다.

| 화면에 뜨는 말 | 실제로 무엇 | 읽는 사람 | 데이터 |
|---|---|---|---|
| **강의계획서** | 한글 양식 그대로 채워 A4 한 장으로 인쇄 | **학교·기관** (제출용) | `lesson_plans` |
| **계획안 첨부파일** | 한글·PPT 원본을 판(版)으로 쌓아둠 | 우리끼리 (보관용) | `plan_files` |
| **강사양성** | 과정 × 강사 이수 매트릭스 | 원장 (진도 확인) | `training_courses` |
| *(새로 만들 것)* | 이 수업을 **어떻게 진행하는지** | **강사 본인** | 새 표 |

그리고 지금 이미 어긋나 있다 — 같은 것을 세 이름으로 부른다:

| 자리 | 지금 문구 |
|---|---|
| `src/app/(app)/apps/[id]/page.tsx:469` | 섹션 제목 **계획안 첨부파일** |
| `src/components/LessonPlan.tsx:84,165,192` | 주석·활동로그 **수업계획안** |
| `src/components/LessonPlan.tsx:261` | 안내 문구 **"지도안 · 활동지 · PPT 를 올려주세요"** |

**여기에 `지도안` 이 이미 쓰이고 있다는 게 핵심이다.** 새 기능을 그냥 '지도안' 이라 부르면
강사가 계획안 첨부 칸에 강사용 지도안을 올린다. 그래서 새 이름을 정하는 김에
**이 세 곳도 같이 정리**한다 (3-2 참고).

---

## 2. 가르는 기준 — 문서 형식이 아니라 **누가 읽는가**

`계획서 / 계획안 / 지도안` 은 한국어에서 뜻이 거의 겹친다.
형식으로 가르면(양식이냐 파일이냐 표냐) 다음 사람이 못 외운다.
**읽는 사람으로 가르면 한 번 듣고 안 잊는다.**

| 이름 | 한 줄 정의 (화면 부제에 그대로 쓴다) |
|---|---|
| **강의계획서** | 학교에 내는 한 장. 우리 내부 사정은 안 실린다 |
| **수업지도안** | 강사가 수업 전에 읽는 진행 순서. 밖으로 안 나간다 |
| **계획안 첨부** | 한글·PPT 원본 보관함. 판이 쌓인다 |

각 화면 맨 위에 이 한 줄을 박아둔다. 이름만으로 안 되면 문장이 해준다.

## 3. 메뉴 이름

### 3-1. 상위 메뉴 — `강사관리` 말고 **`강사교육`**

원장님은 `강사관리` 라고 하셨는데, 이 라벨은 **강사 폰에도 똑같이 보인다.**
강사 입장에서 `강사관리` 는 *"나를 관리하는 곳"* 으로 읽힌다 —
CLAUDE.md 에서 `팀 현황` 을 원장 전용으로 돌린 것과 같은 이유다
(*"강사가 남의 미착수를 봐도 할 수 있는 게 없고 감시처럼 느껴진다"*).

`강사교육` 은 **원장님 말(`강사교육수업지도안`)에 그대로 들어있는 단어**이고,
양성과정과 지도안 둘 다를 자연스럽게 덮는다.

| 후보 | 글자 | 강사가 볼 때 | 판정 |
|---|---|---|---|
| 강사관리 | 4 | "나를 관리한다" | △ |
| **강사교육** | 4 | "내가 배우는 곳" | **○ 추천** |
| 강사양성 (지금) | 4 | 뜻은 맞지만 지도안을 못 덮는다 | △ |

### 3-2. 새 화면 이름 — **`수업지도안`**

| 후보 | 글자 | 장점 | 단점 |
|---|---|---|---|
| 강사교육수업지도안 | 9 | 원장님 말 그대로 | 375px 에서 라벨이 뭉개진다. 사이드바·더보기 칸에 안 들어감 |
| **수업지도안** | 5 | 교육 현장 표준 용어. `강의계획서` 와 표준적으로 갈린다 | 메뉴 밖에서는 "누구용?" 이 흐려진다 → 앞에 `강사교육 ·` 을 붙여 해결 |
| 강사 지도안 | 6 | 읽는 사람이 이름에 있음 | `지도안` 이 계획안 첨부와 겹치는 건 그대로 |
| 강사 매뉴얼 / 진행 가이드 | 6·8 | 뜻이 분명 | 앱 전체가 외래어를 안 쓴다 |

**`수업지도안` 한 단어로 고정한다.** 메뉴(`강사교육`) 안에 있으니 "강사용" 은 자리로 이미 말해진다.
메뉴 밖(활동로그·알림·인쇄)에서는 **단어를 바꾸지 않고 앞에 경로만 붙인다** —
`강사교육 · 수업지도안 — 제과제빵`. 한 물건에 두 이름을 만들지 않는 게 규칙이다.

**같이 정리할 것** (지금 있는 어긋남, 2번 표):
- `LessonPlan.tsx` 의 주석·활동로그 `수업계획안` → **`계획안 첨부`** (화면 라벨과 맞춤)
- 안내 문구 `지도안 · 활동지 · PPT 를 올려주세요` → **`한글·PPT 원본을 올려주세요`**
  (이 자리에서 '지도안' 이라는 말을 뺀다)
- `supabase/schema.sql` 10번 섹션 주석 `수업계획안` → `계획안 첨부(판)`

### 3-3. 왜 메뉴 줄을 새로 안 만드나

- 폰 하단 탭은 **4개 고정**이다 (5개면 375px 에서 라벨이 뭉개진다 — CLAUDE.md)
- `더보기` 시트는 3열 그리드이고 지금 8칸이다. 9칸이 되면 원장은 3줄로 딱 맞지만
  강사는 8칸이라 줄이 어긋난다
- `WORK_NAV` 순서 = 일하는 순서다. 지도안은 **강사양성과 같은 칸**의 일이라
  새 줄이 아니라 그 안의 탭이 맞다

**대신 `/training` 안에서 탭으로 가른다** — 기존 `전체 현황 / 내 과정` 토글과 같은 모양이라
새로 배울 게 없다. 경로가 갈라지므로 링크도 그대로 걸린다
(`isActive` 가 `startsWith('/training/')` 라 사이드바 강조도 그대로 켜진다).

```
강사교육  /training              ← 사이드바 한 줄 (지금 '강사양성' 자리 그대로)
 ├ 양성과정    /training          탭 1 — 지금 화면 그대로
 └ 수업지도안  /training/guide    탭 2 — 신규
                 └ 한 장  /training/guide/[id]
```

## 4. 프로그램 종류별 — **이름을 짓지 않는 것이 답이다**

원장님 질문의 핵심이 여기다. 답은 *"어떤 규칙으로 이름을 붙일까"* 가 아니라
**"이름을 사람이 안 짓게 한다"** 이다.

### 왜 자유 입력이면 안 되나

이 앱은 **이미 두 번 같은 문제를 겪었다.**

| 겪은 일 | 어떻게 됐나 | 어떻게 풀었나 |
|---|---|---|
| 주제를 앱마다 타이핑 (`apps.topic` text) | 같은 주제가 여러 개 생김. *"매번 만들어야 하냐"* | `topics` 표로 빼고 드롭다운 |
| 계획안을 평면 목록으로 쌓기 | `지도안_최종2.hwp` 가 여러 개. 뭐가 최신인지 모름 | `group_id` + `version` 으로 판을 쌓음 |

지도안 제목을 자유 입력으로 두면 **세 번째**가 된다 —
`제과제빵 지도안` · `베이킹 강사교육` · `제과제빵(수정)` 이 같은 프로그램에 생긴다.

### 규칙

1. **지도안 한 장 = 프로그램 하나.** 제목 칸이 아예 없고,
   `apps.title_ko` 를 그대로 제목으로 보여준다.
   → 프로그램 이름을 고치면 **지도안 이름도 같이 바뀐다** (`topics` 와 같은 이유, FK 하나)
2. **목록은 주제별 트리** — `/apps` 와 같은 묶음(`topics`), 같은 접힘 기본값.
   원장님이 말한 "프로그램 종류별" 이 이걸로 끝난다. 주제를 고치면 여기도 따라 바뀐다.
3. **프로그램에 안 걸리는 지도안**(수업 전 준비, 안전 지도, 학부모 응대 같은 것)은
   `app_id` 를 비우고 **`공통`** 묶음에 들어간다. **늘 맨 위**다 —
   `담당자 미정` · `주제 없음` 이 맨 위인 것과 같은 자리다.
   → **`공통` 일 때만 제목 칸이 나온다.** 프로그램이 정해지면 제목은 프로그램이 준다.
4. 프로그램 21개든 200개든 **화면 코드는 그대로.** 새 프로그램을 추가할 때
   지도안 쪽에서 고칠 파일은 **없다** (이 앱의 대전제).

### 화면에 실제로 뜨는 모습

```
수업지도안                                    쓴 것 7 / 21
[전체] [내가 쓴 것] [아직 안 쓴 것]

▸ 공통  2                                  ← 늘 맨 위
▸ 주제 없음  3                             ← 맨 아래 (프로그램 목록과 같은 규칙)
▾ 진로체험  9  ·  쓴 것 4
    제과제빵            ●  이서은  8/12 고침
    조향                ○  아직 안 씀
    화장품              ●  강지연  8/09 고침
```

이름 규칙이 필요한 자리가 **딱 하나** 남는다 — `공통` 지도안의 제목.
여기만 자유 입력이고, 앞에 뭘 붙이라는 규칙을 두지 않는다
(`공통` 묶음 안에 있으니 `[공통] 안전 지도` 처럼 접두어를 또 치면 화면에서 두 번 읽힌다).

## 6. 코드·DB 이름

기존 이름 관습을 그대로 따른다 (`lesson_plans` / `lesson_plan_items` / `plan_files`,
`finding_files` / `comment_files`).

| | 이름 | 왜 |
|---|---|---|
| 경로 | `/training` · `/training/guide` · `/training/guide/[id]` | 사이드바 강조가 `startsWith('/training/')` 로 그대로 켜진다 |
| 표 | `moalab.training_guides` | `training_courses` · `training_records` 와 접두어를 맞춘다. 표 이름만 봐도 `lesson_plans`(학교용)와 갈린다 |
| 항목 | `moalab.training_guide_items` | `lesson_plan_items` 와 같은 꼴 (글 + 사진 한 줄) |
| 첨부 | `moalab.training_guide_files` | `finding_files` · `comment_files` 와 같은 꼴 |
| 버킷 | **`moalab-plans` 재사용** | 성격이 같다(계획 문서 첨부). 버킷을 늘리면 `storage.sql` 을 또 돌려야 한다 |
| 컴포넌트 | `src/components/TrainingGuide.tsx` | 목록·작성 한 파일 (`LessonPlan.tsx` 와 같은 단위) |
| 아이콘 | `board` | `cap` 은 이미 `강사양성` 메뉴와 `강의계획서` 배지가 쓴다 — 겹치면 안 된다 |

표 뼈대 (칸 구성은 7번 참고):

```sql
create table if not exists moalab.training_guides (
  id         uuid primary key default gen_random_uuid(),
  -- 프로그램에 걸면 제목은 apps.title_ko 가 준다. 비우면 '공통' 이고 그때만 title 을 쓴다
  app_id     uuid references moalab.apps(id) on delete cascade,
  title      text,                          -- 공통 지도안일 때만 채워진다
  ...
  updated_by uuid references moalab.members(id) on delete set null,
  updated_at timestamptz not null default now(),
  created_at timestamptz not null default now()
);
-- 프로그램당 한 장. null 은 여러 개 허용되므로 '공통' 은 자유롭게 쌓인다
create unique index if not exists training_guides_app_uniq
  on moalab.training_guides(app_id) where app_id is not null;
```

`app_id` 를 `on delete cascade` 로 둔 것은 **프로그램이 사라지면 그 지도안도 뜻이 없기 때문**이다
(업무·지적처럼 사람 기록으로 남길 것이 아니다 — `lesson_plans` 와 같은 판단).

RLS 는 `schema.sql` 의 `internal_all` 배열에 세 표를 넣는다.
**`members` · `app_secrets` 만 예외**라는 규칙은 그대로 지킨다.

## 7. 칸 이름 (초안 — 원장 확인 필요)

칸 이름도 네이밍이라 여기 같이 적는다. **강의계획서 칸을 그대로 베끼지 않는다** —
저건 학교가 읽는 것이고 이건 강사가 수업 직전에 읽는 것이라 필요한 칸이 다르다.

| 칸 | 무엇을 적나 |
|---|---|
| 준비물·사전 점검 | 수업 전날/당일 아침에 확인할 것 |
| 시간 배분 | 40분/80분을 어떻게 쪼개나 |
| 진행 순서 | 글 + 화면 캡처 한 줄씩 (`training_guide_items`) |
| 자주 나오는 상황 | 아이가 막히는 지점, 기기 안 될 때 |
| 마무리 | 정리·소감·뒷정리 |

CLAUDE.md 의 *"모의수업·강사양성은 뼈대만 만든 상태다 — 실제로 어떤 칸이 필요한지
원장 확인 후 채운다"* 와 같은 자리다. **칸을 확정하기 전에는 표를 만들지 않는다.**

## 9. 확인이 필요한 것 두 가지

1. **"프로그램 종류" 가 프로그램 한 개인가, 주제 묶음인가?**
   이 계획은 **프로그램 한 개**(제과제빵·조향·화장품…)로 잡았다.
   주제(진로체험·문화…) 단위 한 장이면 수업에서 쓰기엔 너무 뭉뚱그려진다고 봤다.
   주제 단위가 맞다면 `app_id` 를 `topic_id` 로 바꾸면 되고, 나머지 계획은 그대로다.
2. **메뉴 이름을 `강사관리` 로 갈지 `강사교육` 으로 갈지** (3-1).
   `강사교육` 을 권하지만 원장님이 부르시던 말이 `강사관리` 면 그대로 가도 된다 —
   라벨 한 줄이라 나중에 바꾸는 비용도 없다.
