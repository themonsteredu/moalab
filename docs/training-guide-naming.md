# 웹앱 교육안 · 양식 올리기 — 이름 짓기 계획

> **하려는 것**: 웹앱(프로그램)마다 **강사교육용 교육안과 양식을 문서 파일로 올려둔다.**
> 화면에 칸을 채우는 게 아니라 한글·PPT·PDF 를 올리는 것이다.
>
> **어디에**: 새 메뉴를 만들지 않고 **프로그램 페이지(`/apps/[id]`) 안에서 끝낸다.**

---

## 0. 결론 세 줄

1. **새 메뉴도, 새 표도, 새 버킷도 만들지 않는다.** `/apps/[id] > 계획안 첨부파일` 이
   이미 판(版) 쌓기·미리보기·zip 받기까지 갖춘 문서함이다. 안내 문구가 지금도
   *"지도안 · 활동지 · PPT 를 올려주세요"* 다 — **올릴 자리가 이미 있다.**
2. 필요한 건 딱 하나, **문서 갈래(`kind`) 칸** — `계획안` / `교육안` / `양식` / `기타`.
3. **묶음 이름은 사람이 짓지 않는다.** 프로그램 페이지 안이라 프로그램 이름이 이미 제목이고,
   `/apps` 목록이 이미 주제별 트리다 — "프로그램 종류별" 이 **공짜로 이미 되어 있다.**

---

## 1. 왜 프로그램 쪽인가

이 앱의 원래 판단이 그쪽이다. CLAUDE.md — **"프로그램 페이지 — '따로국밥' 을 없앤 곳"**:

> 노션에서 가장 답답했던 게 **웹앱 · 검증 · 수업계획안 · 원가 · 샘플이미지가 다 딴 데** 있던 것이다.
> 그래서 `/apps/[id]` 한 페이지에 전부 올렸다.

교육안만 다시 다른 메뉴로 빼면 그 결정을 거스른다. **제과제빵 수업을 나가는 강사는
제과제빵 한 페이지만 열면 된다** — 검증도 원가도 교육안도 거기 있다.

### 따로 메뉴를 만들 근거가 약했다

앞선 계획에서 *"프로그램 페이지를 21번 들락거려야 한다"* 를 근거로 들었는데 **틀렸다.**
`주제로 옮기기` · `나눠주기` 는 **한 값을 여러 줄에** 찍는 일이라 왕복이 낭비였다.
교육안은 프로그램마다 **다른 파일**이라 어차피 한 번씩 들어가야 한다 — 왕복이 안 줄어든다.

### 나중에 필요해지면

강사가 *"이번에 나갈 자료 어디 있지"* 를 자주 헤매면 그때 `강사양성` 옆에
모아보는 화면을 얹는다. **지금 갈래 칸을 넣어두면 그때 데이터는 이미 맞아 있어서
화면만 얹으면 된다** (`/verify` 가 새 표 없이 만들어진 것과 같은 방식).
지금 안 만드는 것이지, 못 만들게 하는 게 아니다.

## 2. 이미 있는 것 — 새로 만들 게 별로 없다

`src/components/LessonPlan.tsx` (표 `moalab.plan_files`, 버킷 `moalab-plans`) 가 하는 일:

| 되는 것 | 어디에 |
|---|---|
| 한글 · PDF · PPT · 엑셀 · 이미지 올리기 | `onFiles()` |
| **문서 하나 = 카드 하나, 고쳐 올리면 다음 판** | `group_id` + `version` |
| 누가 올렸나 · 이번에 바꾼 것 | `member_id` · `note` |
| 지난 판 접어두고 그대로 받기 | `openHistory` |
| 최신 판만 zip 으로 전체 받기 | `downloadAll()` |
| PDF·이미지 미리보기, 확장자 색 라벨 | `previewKind()` · `FileBadge` |

원장님이 원하는 **"양식들을 문서로 올린다"** 가 이 코드 그대로다.

## 4. 문서 갈래 — 여기가 진짜 네이밍이다

파일 올리는 자리는 하나로 두고, **무엇을 올린 건지만 갈래로 표시**한다.

| 갈래 | 무엇을 올리나 | 누가 읽나 | 칩 색 |
|---|---|---|---|
| `계획안` *(기본값)* | 지금까지 올려온 프로그램 계획 문서 | 우리끼리·학교 | 회색 |
| **`교육안`** | 이 웹앱 수업을 **어떻게 진행하는지** | **강사** | 브랜드 |
| **`양식`** | 활동지·학습지·평가지 — 인쇄해 나눠주는 것 | 학생 | teal |
| `기타` | PPT·영상·참고자료 | — | 회색 |

- **가르는 기준은 문서 형식이 아니라 누가 읽는가다.** 형식으로 가르면
  (한글이냐 PPT냐) 확장자 라벨과 겹치기만 하고 아무것도 안 알려준다.
- **네 개에서 멈춘다.** 갈래를 늘리면 올릴 때마다 고민이 늘고, 375px 에서 칩이
  두 줄로 접힌다 (지출결의서에서 구분 7개 + 사람 5명을 깔았다가 겪은 일).
- **기본값은 `계획안`** — 지금 올라가 있는 파일이 전부 그것이라, 칸을 더해도
  **화면이 지금과 똑같이 보인다.** 지난 파일의 뜻이 안 바뀐다.
- `교육안` 과 `계획안` 이 한 글자 차이라 소리로는 비슷하다. 화면에서는 **늘 다른 색 칩**으로
  붙어 나오고 섹션 부제에 한 줄 정의가 있어서 눈으로는 안 헷갈린다.
  · 그래도 걸리면 **`강사용`** 으로 간다 — 읽는 사람이 이름에 그대로 있어 가장 안 헷갈린다.
    라벨 한 줄이라 나중에 바꿔도 비용이 없다.

## 5. 프로그램 종류별 — **이미 되어 있다**

원장님 질문의 핵심이 여기였는데, 프로그램 쪽에 넣기로 하면 **따로 할 일이 없다.**

| 걱정했던 것 | 프로그램 페이지 안에서는 |
|---|---|
| 종류별로 어떻게 나누지 | `/apps` 가 이미 **주제별 트리**다 |
| 문서 묶음 이름을 뭐라 짓지 | 페이지 제목이 이미 프로그램 이름이다 |
| 이름이 제각각 되면 | 제목 칸 자체가 없다 — 지을 일이 없다 |

**파일 이름도 올린 그대로 둔다.** 이름 규칙을 강제하면 올리기 전에 파일 이름을 고쳐야 해서
아무도 안 올린다. 대신 **갈래 칩 + 판 번호 + 올린 사람**이 파일 이름을 대신 설명한다.
규칙이 붙는 건 내려받을 때뿐이다 — `제과제빵_문서.zip` (최신 판만 묶는 지금 방식 그대로).

프로그램이 21개든 200개든 **화면 코드는 그대로.** 새 프로그램을 추가할 때 고칠 파일은 **없다.**

## 7. 코드·DB

```sql
-- 문서 갈래. 지금까지 올린 것은 전부 계획안이었으므로 그게 기본값이다
alter table moalab.plan_files add column if not exists kind text not null default 'plan'
  check (kind in ('plan','guide','form','etc'));
```

| | 이름 | 왜 |
|---|---|---|
| 표 | **`plan_files` 그대로** | 새 표를 만들면 판 쌓기·zip·미리보기를 두 벌 관리하게 된다 |
| 새 칸 | `kind` (`plan`·`guide`·`form`·`etc`) | 한글 라벨은 `types.ts` 상수로 (`FINDING_META` 와 같은 꼴) |
| 버킷 | **`moalab-plans` 그대로** | 성격이 같다. 버킷을 늘리면 `storage.sql` 을 또 돌려야 한다 |
| 컴포넌트 | `LessonPlan.tsx` 안에서 | 새 컴포넌트를 안 만든다. 올릴 때 갈래를 고르고, 목록에서 갈래로 거른다 |
| 메뉴 | **안 건드린다** | `강사양성` 그대로. `BottomNav.tsx` 수정 없음 |

RLS 는 `plan_files` 가 이미 `internal_all` 배열에 있어서 **건드릴 게 없다.**

**카드 배지**(`useAppsOverview` 의 `PIECES`)는 지금 6개가 한 줄이다. `교육안` 을 더하면
7개가 되어 375px 에서 두 줄로 접힐 수 있다 — 실제로 재보고(`scripts/measure.mjs`)
접히면 안 넣는다. 배지는 "빠진 것 찾기" 용이라 꼭 필요하면 `계획안` 배지의 뜻을
'문서가 하나라도 있음' 으로 넓히는 쪽이 낫다.

## 9. 남겨둔 것

- 갈래는 **넷에서 멈췄다.** 나중에 늘리면 이미 올린 파일을 다시 분류해야 한다.
- `교육안` / `강사용` 중 **`교육안`** 으로 갔다 (원장이 쓰신 말).
  `계획안` 과 소리가 비슷한 게 실제로 걸리면 `types.ts` 의 `PLAN_KINDS` 라벨 한 줄이다.
- 강사가 *"이번에 나갈 자료 어디"* 를 자주 헤매면 그때 **모아보는 화면**을 얹는다.
  `kind` 가 이미 있어서 새 표 없이 화면만 얹으면 된다 (1번의 "나중에 필요해지면").
