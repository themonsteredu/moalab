# 웹앱 교육안 · 양식 올리기 — 이름 짓기 계획

> **하려는 것**: 웹앱(프로그램)마다 **강사교육용 교육안과 양식을 문서 파일로 올려두고**,
> 강사가 수업 나가기 전에 찾아 쓰게 한다.
>
> 화면에 칸을 채우는 게 아니라 **한글·PPT·PDF 파일을 올리는 것**이다. 이 차이가 계획을
> 통째로 바꾼다 — 만들 게 훨씬 적다.

---

## 0. 결론 네 줄

1. **업로드함을 새로 만들지 않는다.** `/apps/[id] > 계획안 첨부파일` 이 이미
   판(版) 쌓기·미리보기·zip 받기까지 갖춘 문서함이다. 안내 문구가 지금도
   *"지도안 · 활동지 · PPT 를 올려주세요"* 다 — 원장님이 올리려는 것이 **이미 올릴 자리가 있다.**
2. 필요한 건 딱 하나, **문서 갈래(`kind`) 칸**. `계획안 / 교육안 / 양식 / 기타`.
3. **메뉴는 `강사교육`** (지금 `강사양성` 자리) 안에 탭 두 개 — `양성과정` / **`교육자료`**.
   이 화면은 **새 표 없이 기존 파일을 강사 눈으로 다시 모아 보여주는 것**이다
   (`/verify` 가 새 테이블 없이 만들어진 것과 같은 방식).
4. **문서 이름은 사람이 짓지 않는다.** 프로그램을 고르면 프로그램 이름이 곧 묶음 이름이고,
   목록은 `/apps` 와 같은 주제별 트리다 — "프로그램 종류별" 이 공짜로 된다.

## 1. 이미 있는 것부터 — 새로 만들 게 별로 없다

`src/components/LessonPlan.tsx` (표 `moalab.plan_files`, 버킷 `moalab-plans`) 가
지금 하는 일:

| 되는 것 | 어디에 |
|---|---|
| 한글 · PDF · PPT · 엑셀 · 이미지 올리기 | `onFiles()` |
| **문서 하나 = 카드 하나, 고쳐 올리면 다음 판** | `group_id` + `version` |
| 누가 올렸나 · 이번에 바꾼 것 | `member_id` · `note` |
| 지난 판 접어두고 그대로 받기 | `openHistory` |
| **최신 판만 zip 으로 전체 받기** | `downloadAll()` |
| PDF·이미지 미리보기, 확장자 색 라벨 | `previewKind()` · `FileBadge` |

원장님이 원하는 **"양식들을 문서로 올린다"** 는 이 코드 그대로다.
**새 표·새 버킷·새 업로드 코드가 필요 없다.**

## 2. 지금 이 앱에 '계획' 이 이미 세 개다

새 이름을 정하기 전에, 뭐가 헷갈리는지부터 봐야 한다.

| 화면에 뜨는 말 | 실제로 무엇 | 읽는 사람 | 데이터 |
|---|---|---|---|
| **강의계획서** | 한글 양식 그대로 채워 A4 한 장으로 인쇄 | **학교·기관** (제출용) | `lesson_plans` |
| **계획안 첨부파일** | 한글·PPT 원본을 판으로 쌓아둠 | 우리끼리 (보관용) | `plan_files` |
| **강사양성** | 과정 × 강사 이수 매트릭스 | 원장 (진도 확인) | `training_courses` |

그리고 이미 어긋나 있다 — 같은 것을 세 이름으로 부른다:

| 자리 | 지금 문구 |
|---|---|
| `src/app/(app)/apps/[id]/page.tsx:469` | 섹션 제목 **계획안 첨부파일** |
| `src/components/LessonPlan.tsx:84,165,192,214,217` | 주석·활동로그·zip 이름 **수업계획안** |
| `src/components/LessonPlan.tsx:261` | 안내 문구 **"지도안 · 활동지 · PPT 를 올려주세요"** |

**여기에 '지도안' 이 이미 쓰이고 있다.** 새 기능을 '지도안' 이라 부르면
강사가 계획안 첨부 칸에 강사교육안을 올린다. 실제로 그 문구가 그렇게 시킨다.

## 3. 가르는 기준 — 문서 형식이 아니라 **누가 읽는가**

`계획서 / 계획안 / 교육안` 은 뜻이 거의 겹친다. 형식으로 가르면(양식이냐 파일이냐)
다음 사람이 못 외운다. **읽는 사람으로 가르면 한 번 듣고 안 잊는다.**

| 이름 | 한 줄 정의 (화면 부제에 그대로 쓴다) |
|---|---|
| **강의계획서** | 학교에 내는 한 장. 우리 내부 사정은 안 실린다 |
| **교육안** | **강사가 수업 전에 읽는 진행 문서** |
| **양식** | 인쇄해서 아이들에게 나눠주는 서식 (활동지·학습지) |
| **계획안** | 프로그램 계획 원본 보관함. 판이 쌓인다 |

## 4. 문서 갈래 — 여기가 진짜 네이밍이다

파일을 올리는 자리가 하나이므로, **무엇을 올린 건지 갈래로 표시**한다.
`plan_files` 에 `kind` 칸 하나를 더한다.

| 갈래 | 무엇을 올리나 | 누가 읽나 | 칩 색 |
|---|---|---|---|
| `계획안` *(기본값)* | 지금까지 올려온 프로그램 계획 문서 | 우리끼리·학교 | 회색 |
| **`교육안`** | 이 웹앱 수업을 **어떻게 진행하는지** | **강사** | 브랜드 |
| **`양식`** | 활동지·학습지·평가지 — 인쇄해 나눠주는 것 | 학생 | teal |
| `기타` | PPT·영상·참고자료 | — | 회색 |

- **네 개에서 멈춘다.** 갈래를 늘리면 올릴 때마다 고민이 늘고, 375px 에서 칩이
  두 줄로 접힌다 (지출결의서에서 구분 7개 + 사람 5명을 깔았다가 겪은 일).
- **기본값은 `계획안`** — 지금 올라가 있는 파일이 전부 그것이고,
  칸을 더해도 지난 파일의 뜻이 안 바뀐다.
- `교육안` 과 `계획안` 이 한 글자 차이라 소리로는 비슷하다. 화면에서는 **늘 다른 색 칩**으로
  붙어 나오고 각 화면 부제에 위 한 줄 정의가 있어서 눈으로는 안 헷갈린다.
  · 그래도 걸리면 `교육안` 대신 **`강사용`** 으로 간다 — 읽는 사람이 이름에 그대로 있어
  가장 안 헷갈리는 후보다. 라벨 한 줄이라 나중에 바꿔도 비용이 없다.

## 5. 메뉴 이름

### 5-1. 상위 메뉴 — `강사관리` 말고 **`강사교육`**

`강사관리` 는 **강사 폰에도 똑같이 보이는 라벨**이다. 강사 입장에서는
*"나를 관리하는 곳"* 으로 읽힌다 — CLAUDE.md 에서 `팀 현황` 을 원장 전용으로 돌린 것과
같은 이유다 (*"강사가 남의 미착수를 봐도 할 수 있는 게 없고 감시처럼 느껴진다"*).

`강사교육` 은 **원장님 말(`강사교육수업지도안`)에 그대로 들어있는 단어**이고,
양성과정과 교육자료 둘 다를 덮는다.

### 5-2. 새 화면 — **`교육자료`**

여러 갈래(교육안·양식)를 담는 **그릇**이라 그릇 이름을 쓴다.
갈래 이름(`교육안`)을 화면 이름으로도 쓰면 *"교육안 안에 교육안"* 이 된다.

| 후보 | 글자 | 판정 |
|---|---|---|
| 강사교육수업지도안 | 9 | ✗ 375px 에서 라벨이 뭉개진다. 사이드바·더보기 칸에 안 들어감 |
| **교육자료** | 4 | **○ 추천** — 갈래 여럿을 담는 그릇 이름 |
| 교육안 | 3 | △ 갈래 이름과 겹친다 |
| 자료실 | 3 | △ 무엇에 대한 자료인지 안 보인다 |

### 5-3. 메뉴 줄은 안 늘린다

- 폰 하단 탭은 **4개 고정**이다 (5개면 375px 에서 라벨이 뭉개진다)
- `더보기` 시트는 3열 그리드이고 지금 원장 8칸 · 강사 7칸이다
- `WORK_NAV` 순서 = 일하는 순서다. 교육자료는 **강사양성과 같은 칸**의 일이다

```
강사교육  /training            ← 사이드바 한 줄 (지금 '강사양성' 자리 그대로)
 ├ 양성과정   /training         탭 1 — 지금 화면 그대로
 └ 교육자료   /training/docs    탭 2 — 신규
```

`isActive` 가 `startsWith('/training/')` 라 **사이드바 강조는 그대로 켜진다.**

## 6. 프로그램 종류별 — **이름을 짓지 않는 것이 답이다**

원장님 질문의 핵심이 여기다. 답은 *"어떤 규칙으로 이름을 붙일까"* 가 아니라
**"이름을 사람이 안 짓게 한다"** 이다.

### 왜 자유 입력이면 안 되나

이 앱은 **이미 두 번 같은 문제를 겪었다.**

| 겪은 일 | 어떻게 됐나 | 어떻게 풀었나 |
|---|---|---|
| 주제를 앱마다 타이핑 (`apps.topic` text) | 같은 주제가 여러 개. *"매번 만들어야 하냐"* | `topics` 표 + 드롭다운 |
| 계획안을 평면 목록으로 쌓기 | `지도안_최종2.hwp` 가 여러 개. 뭐가 최신인지 모름 | `group_id` + `version` |

문서 묶음 제목을 자유 입력으로 두면 **세 번째**가 된다 —
`제과제빵 교육안` · `베이킹 강사교육` · `제과제빵(수정)` 이 같은 웹앱에 생긴다.

### 규칙

1. **묶음 이름 = 프로그램 이름.** 제목 칸이 없다. `apps.title_ko` 를 그대로 쓴다.
   → 프로그램 이름을 고치면 **여기 이름도 같이 바뀐다** (`topics` 와 같은 이유, FK 하나)
2. **목록은 주제별 트리** — `/apps` 와 같은 묶음(`topics`), 같은 접힘 기본값.
   "프로그램 종류별" 이 이걸로 끝난다.
3. **파일 이름은 올린 그대로 둔다.** 이름을 강제하면 올리기 전에 파일 이름을 고쳐야 해서
   아무도 안 올린다. 대신 **갈래 칩 + 판 번호 + 올린 사람**이 파일 이름을 대신 설명한다.
   · 내려받을 때만 규칙이 붙는다 — `제과제빵_교육자료.zip` (최신 판만 묶는 지금 방식 그대로)
4. 프로그램이 21개든 200개든 **화면 코드는 그대로.** 새 프로그램을 추가할 때
   여기서 고칠 파일은 **없다** (이 앱의 대전제).

### 화면에 실제로 뜨는 모습

```
교육자료                                    교육안 있는 것 7 / 21
[교육안] [양식] [전체]                        + 올리기

▾ 진로체험  9  ·  교육안 4
    제과제빵      [교육안 2판] [양식]        이서은 · 8/12
    조향          아직 없음
    화장품        [교육안]                   강지연 · 8/09
▸ 문화  6  ·  교육안 2
▸ 주제 없음  3                              ← 늘 맨 아래 (프로그램 목록과 같은 규칙)
```

### 21번 들락거리지 않게

프로그램 페이지에 하나씩 들어가서 올리면 **21번 왕복**이다.
`주제로 옮기기` · `나눠주기` 와 똑같은 문제라 똑같이 푼다 —
**교육자료 화면에서 프로그램을 고르고 바로 올린다.** 화면을 안 옮긴다.

## 9. 코드·DB

```sql
-- 문서 갈래. 지금까지 올린 것은 전부 계획안이었으므로 그게 기본값이다
alter table moalab.plan_files add column if not exists kind text not null default 'plan'
  check (kind in ('plan','guide','form','etc'));
create index if not exists plan_files_kind_idx on moalab.plan_files(kind, app_id);
```

| | 이름 | 왜 |
|---|---|---|
| 표 | **`plan_files` 그대로** | 새 표를 만들면 판 쌓기·zip·미리보기를 두 벌 관리하게 된다 |
| 새 칸 | `kind` (`plan`·`guide`·`form`·`etc`) | 영문은 짧게, 한글 라벨은 `src/lib/types.ts` 의 상수로 (`FINDING_META` 와 같은 꼴) |
| 버킷 | **`moalab-plans` 그대로** | 성격이 같다. 버킷을 늘리면 `storage.sql` 을 또 돌려야 한다 |
| 경로 | `/training` · `/training/docs` | 사이드바 강조가 `startsWith('/training/')` 로 그대로 켜진다 |
| 컴포넌트 | `LessonPlan.tsx` 에 `kind` prop 추가 | 갈래로 거르고 올릴 때 갈래를 정한다. 새 컴포넌트를 안 만든다 |
| 새 화면 | `src/app/(app)/training/docs/page.tsx` | **새 데이터 없음** — `plan_files` + `apps` + `topics` 재조합 |
| 아이콘 | `clip` | 첨부와 같은 것을 가리키니 아이콘도 같아야 한다 (`cap` 은 이미 `강사양성`·`강의계획서` 가 쓴다) |

RLS 는 `plan_files` 가 이미 `internal_all` 배열에 있어서 **건드릴 게 없다.**

## 10. 만드는 순서

1. **말부터 정리** (8번) — 코드가 안 늘어나고, 안 하면 아래가 전부 헷갈린다
2. `plan_files.kind` 한 칸 + `types.ts` 에 갈래 상수 (`schema.sql` 에도 반영, 재실행 안전하게)
3. `LessonPlan` 에 갈래 칩 — 올릴 때 고르고, 목록에서 거른다.
